# Graph Module

Own source discovery/schema provenance, bounded Graph queries and both explicit access modes. Consult sponsor/graph.md before implementation. Credential failure must not fall back to wallet-funded x402; adapters require live evidence.

Expose provider-neutral ports for `searchSubgraphs`, `getSubgraphSchema`, `generateGraphQL`, and `executeGraphQL`. The Graph Subgraph MCP can implement discovery, schema retrieval and execution, but it does not generate Sprue's GraphQL semantics or provide a model. GraphQL generation and static validation remain Sprue-owned. Keep MCP operation names, URLs and SDK types inside this adapter; a direct Graph API implementation must be substitutable without changing the Agent or DAG modules. Execution is authorized data-plane work and must receive an explicit access context, budget and stored query plan.

Use existing Subgraphs only. Select by evidenced semantic fit, coverage, freshness, and query costs; report source gaps instead of creating/deploying Subgraphs, Subgraph Composition, or another ingestion path. Multiple source adapters may supply a downstream Union/Join DAG, but each source remains separately pinned, queried and accounted for. Keep query capabilities distinct from new indexing work. See the [confirmed boundary](../../../../agents.md#confirmed-existing-subgraph-boundary).

Status: the provider-neutral planning port, restricted hosted Graph MCP client, deterministic schema inspection, 30-day activity collection for every bounded candidate, independent per-SourceNeed keyword/contract discovery, per-need schema inspection, and candidate ranking are implemented against The Graph mainnet environment. Before the adapter is called, the Harness turns protocol, canonical asset-symbol pairs, semantic keyword hints, and the server-owned network label into an independent bounded search set for each SourceNeed; identical model hints therefore cannot collapse different networks into one shared search pool. Symbols do not establish a token identity, and a network-specific asset identifier still requires explicit creator input or inspected source evidence. Activity orders schema inspection from highest to lowest observed use, with missing observations last; zero or missing activity never blocks inspection. The inspector reads explicit `Query` roots when present and otherwise verifies collection roots with one fixed runtime-introspection document; it does not guess pluralized query names. Candidate adoption ranking combines network evidence, lexical fit to the model's bounded search keywords, inspected row-grain fit, compatible field evidence, and advisory activity. Compact entity-selection evidence is allocated round-robin across ranked candidates so one broad but irrelevant schema cannot consume the complete per-need entity budget. Field matching accepts ordered semantic identifier tokens such as `amountUSD` in `amountInUSD`, while retaining penalties for cumulative or nested aggregate metrics at event grain. The default per-need budget is three searches, ten candidates per search, and ten inspected schemas. Every deduplicated candidate inside that inspection budget is inspected; candidate order cannot make the controller stop after the first superficially suitable result. The planning client exposes no model- or browser-controlled `execute_query_*` method and never supplies the model with the remote tool catalog, endpoint, credential, provider descriptions, or raw SDL. It accepts a server-side Graph Gateway credential only through constructor injection; resolving that credential from the authenticated workspace remains an application-service responsibility.

`AgentHarness.explore` is the ordered planner entry point when a discovery port is injected. It asks the configured model for a strict semantic/search plan with dynamically named source requirements, field requirements, and result fields; maps the validated keywords to this module's fixed discovery method; and invokes a second model stage only after inspection to select exact inspected field paths and propose a registered-operator topology. `AgentHarness.discoverGraphSources` remains a lower-level deterministic entry point for tests and application services that already own a validated discovery request. Both return inspected candidate evidence and a validated feasibility proposal, not an executable source binding. A caller must still resolve and persist a workspace-owned immutable source snapshot, distinguish the logical Subgraph ID, gateway Deployment ID, and manifest IPFS CID, validate historical coverage/freshness through an authorized bounded query, compile and validate the bounded GraphQL document from the selected mappings, and obtain an explicit source access selection. The evaluator runtime continues to use labeled fixtures and does not combine live MCP metadata with fixture rows.

Domain repositories, handlers, live Graph execution, payment, and durable discovery audit records are not implemented. The owning HTTP routes remain reserved and fail closed. Keep domain behavior independent of Express, process environment and hosting providers; inject repositories and provider ports from src/app.
