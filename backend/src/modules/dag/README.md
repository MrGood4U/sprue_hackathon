# Dag Module

Own the eight-type source/filter/map/aggregate/sort/union/join/output registry, deterministic compiler and interpreter. The version-2 generic Filter predicate and version-1 Sort / Top K contract are approved and implemented; other H1 exact executable schemas remain unapproved. Semantic templates compile to primitives; no unrestricted code fallback is enabled.

The first runtime slice is implemented in [runtime.ts](runtime.ts). It validates a schema-provided field mapping, normalizes provider rows into the canonical Swap contract, performs exact decimal arithmetic, applies the type-checked generic Filter engine from [filter.ts](filter.ts), aggregates by wallet and chain, unions source lineage, and joins one aggregate per wallet across two chains. The pure [Map engine](map.ts) validates and executes the bounded expression AST for explicit type and epoch-unit conversion, text normalization and concatenation, null fallback, exact decimal arithmetic, and deterministic numeric rounding. Each Map output may also carry a bounded generic unit annotation; null inherits an inferred unit, while a string annotates metadata without changing the value. No unit is inferred from a field name or provider convention. The pure [Sort / Top K engine](sort.ts) provides stable typed multi-key ordering and bounded Top K selection for the generic DAG path. A live Agent may author an equivalent bounded GraphQL predicate or cursor-compatible sort pushdown for a Source; after the complete semantic composition passes validation, the backend freezes that query and removes only the exactly equivalent Filter or Sort work. Raw selected paths remain Source outputs and every provider-to-semantic rename, flattening, conversion, unit annotation, and derivation remains explicit in the mandatory project-mode Map boundary.

The Builder compiler is implemented in [compiler.ts](compiler.ts). It accepts only the bounded layout-free eight-operator DAG contract, rejects invalid node and edge references, ports, input cardinality, cycles, unreachable branches, unsupported operator versions or configurations, invalid Source output connections, incompatible predecessor-derived schemas, and a mismatched declared Output schema. A passing response includes a deterministic canonical hash for that exact request. The control-plane build then admits the exact selected sources and persists or reuses a hash-bound ready version; it does not execute result rows or activate a deployment.

The generic hosted live runtime is implemented in `../deployments/runtime.ts`. Deployment loads an immutable ready plan instead of generating endpoint-specific code. Each accepted API-key request verifies the plan hash, executes its stored static GraphQL documents against The Graph, then evaluates the fixed DAG in topological order. Result rows are request-local and are never cached or reused. Plans pin page and row limits, source snapshots, credential references, field bindings, operator versions, and output schema; credentials remain server-side. Reaching a Source row ceiling stops pagination and continues over the bounded prefix while delivery metadata sets `sourceRowLimitReached`; exhausting the request budget before that ceiling still fails. Agent Filter pushdown may use inspected non-list, non-null nested relationship paths only when its bounded canonicalizer proves the complete GraphQL and DAG AND/OR predicates equivalent; final source admission still validates the authored query against the pinned provider SDL.

The runtime deliberately does not discover Subgraphs, call Graph MCP, generate GraphQL, schedule jobs, invoke an Agent, authorize wallets, settle x402 payments, or expose HTTP handlers. Those provider and application ports remain outside this pure module. The captured JSON files under [backend/tests/fixtures](../../tests/fixtures) are live-shape samples, not current-window coverage or payment evidence.

Keep the runtime independent of Express, process environment and hosting providers. Before enabling handlers, connect it through the durable product-version and execution-run records, add source/query provenance, enforce workspace budgets, and replace fixtures with the Graph adapter. Do not add database fields ad hoc; update [data-model.md](../../../data-model.md) first if the implementation reveals a missing concept.
