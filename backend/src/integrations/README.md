# Provider Adapter Boundary

Production composition installs the Privy access-token verifier only when both `PRIVY_APP_ID` and `PRIVY_APP_SECRET` are configured. Missing or partial configuration fails closed through `unavailable-identity.ts`. Test verifiers remain dependency-injected; never add a production configuration switch accepting arbitrary user IDs or decoded-only JWTs.

The authentication adapter verifies provider-signed access tokens through the official server SDK and maps the validated Privy subject to a provider identity key. The authentication module resolves that key through `auth_identities` to an application-owned Sprue user UUID. Wallet signing is a distinct adapter with distinct authority. Graph and Hedera/Blocky402 integrations remain unimplemented. The temporary evaluator runtime has a bounded OpenAI-compatible model port, but durable model-secret management, metering, rotation, and recovery remain unimplemented. Keep provider clients, secrets and raw errors out of domain modules and HTTP DTOs.
